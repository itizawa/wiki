# 点検の観点

サブエージェントは、割り当てられた画面ごとにこの順で見る。全部を毎回深く見なくてよいが、「表示崩れ」と「UX」の両方を必ず見る。

## 表示崩れ（幅ごと）

まず `layout-probe.js` を `javascript_tool` で走らせ、数字で拾う。そのあと `computer` のスクリーンショットで目で確かめる（数字だけで issue にしない）。上から下までスクロールして、全部を見る。

- **横のはみ出し**: ページ全体が横にスクロールする（`horizontalOverflow`）。どの要素が原因か（`overflowing`）。WCAG 1.4.10（リフロー）では 320px 幅で横スクロールが出てはいけない。表・コードブロックなど、それ自体が横にスクロールするものは除く
- **重なり・はみ出し**: 文字やボタンがほかの要素に重なる、枠の外に出る、固定のヘッダーや下のバーが中身を隠す
- **切れる文字**: 長いタイトル・日本語の長い語・URL・メールアドレスが、省略記号も無く途中で切れる（`clipped`）。逆に、省略されて全文を見る手段が無い
- **押しにくい**: 押せる部分が 24×24px 未満（WCAG 2.5.8、`smallTargets`）。スマホでは 44×44px を目安にする（Apple HIG 44pt、Material 48dp）。隣り合うボタンが近すぎて押し間違える
- **スマホの入力**: 入力欄の文字が 16px 未満（`smallInputs`）。iOS の Safari は入力欄にフォーカスすると勝手に拡大する
- **配置の切り替わり**: MUI の md（900px）の前後で、サイドバー・ツールバー・ダイアログの配置が破綻しない。ダイアログやメニューが画面の外に出ない、閉じるボタンが見える
- **空・多い・長い**: 一覧が空のとき、件数が多いとき、タイトルが長いときに崩れない
- **読み込み中**: 読み込みの前後で中身が大きくずれない（レイアウトシフト）。スケルトンや「読み込み中」がある
- **画像・アイコン**: 歪む、はみ出す、ぼやける

## UX

[ニールセンの10のユーザビリティ原則](https://www.nngroup.com/articles/ten-usability-heuristics/) を、この wiki に当てはめて見る。

1. **状態がわかる**: 保存中・保存済み・公開済み・予約済みが画面からわかる。押したあとに何か起きたかわかる（読み込み表示、トースト）
2. **言葉が利用者のもの**: 内部の言葉（ID、英語のエラー、スタックトレース）がそのまま出ていない。同じものを画面ごとに違う名前で呼んでいない（例: 「削除」と「ゴミ箱に入れる」）
3. **やり直せる**: 消す・公開するなど戻しにくい操作に確認か取り消しがある。ダイアログを Esc や外側のクリックで閉じられる。戻るボタンで期待どおり戻れる
4. **一貫している**: ボタンの位置・色・並び順、一覧の行を押したときの動き（CLAUDE.md: 遷移先のある行はどこを押しても移れる）が画面ごとにそろっている
5. **間違いを防ぐ**: 入力の制限（文字数、形式）を、送る前にわかるように出す。押せない状態のボタンに理由がある
6. **思い出させない**: 今どの wiki・どのページにいるかがわかる。必要な情報が別の画面に行かないと見えない、ということが無い
7. **慣れた人の近道**: キーボードショートカット、コマンドメニューが使える。よく使う操作が奥に埋まっていない
8. **余計なものが無い**: 1画面に情報や操作が詰め込まれすぎていない。スマホで、大事な操作が下のほうに追いやられていない
9. **エラーから立ち直れる**: エラーの文が、何が起きて次に何をすればよいかを言っている。404・権限なし・通信失敗の画面がある
10. **助け**: 初めて見る人に、空の画面で次に何をすればよいかがわかる（空の状態の案内）

あわせて見る:

- **キーボード**: Tab で順に移れる。フォーカスが見える。ダイアログを開くとフォーカスが中に入り、閉じると元に戻る
- **スマホ**: `:hover` でしか出ない操作が無い（スマホでは押せない）。片手で届く位置に主な操作がある
- **コンソールと通信**: `read_console_messages`（`pattern: "error|warn|Error"`）と `read_network_requests` で、エラーや失敗したリクエスト（4xx/5xx）が無いか
- **読みやすさ**: 文字と背景のコントラストが低すぎない（WCAG 1.4.3 で本文は 4.5:1）。行が長すぎない

## 重大度

[ニールセンの重大度](https://www.nngroup.com/articles/how-to-rate-the-severity-of-usability-problems/) を 1〜4 で使う（0 は「問題ではない」なので起票しない）。

| 重大度 | 目安 | 例 |
|---|---|---|
| 4 | 使えない。目的の操作ができない、データを失う | スマホで保存ボタンが画面外に出て押せない |
| 3 | 大きい。多くの人が困る、回り道が要る | 一覧が横にはみ出して、右端の操作が見えない |
| 2 | 小さい。気づけば避けられる | 押せる部分が小さく、押し間違えやすい |
| 1 | 見た目だけ | 余白の不揃い、1px のずれ |

迷ったら、どれだけの人が（頻度）、どれだけ困るか（影響）、毎回か（持続）で決める。

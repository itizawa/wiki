# サブエージェントへの指示のひな形

`{ }` を埋めて、`general-purpose` のサブエージェントに渡す。サブエージェントはこのリポジトリのファイルを読めるので、観点とスクリプトはパスで渡す。

## 表示崩れの点検（幅ごと・画面の組ごと）

```
あなたは wiki（itizawa/wiki）の画面を、Claude in Chrome で点検する担当です。見つけたことを返すだけで、issue は作りません。

## 前提
- 対象: {本番 / 手元}（{https://wiki-admin.hatchery-works.com など}）
- 中身の幅: {375} CSS px（親が測った window.innerWidth。拡大率 {100}%）
- 担当の画面:
  1. {画面の名前} — {URL}
  2. ...

## 守ること
- 最初に anthropic-skills:chrome-browser スキルを読む。Chrome の道具は ToolSearch 1回でまとめて読み込む（tabs_context_mcp, tabs_create_mcp, tabs_close_mcp, navigate, computer, read_page, find, javascript_tool, read_console_messages, read_network_requests）
- tabs_context_mcp のあと tabs_create_mcp で自分のタブを1つ開き、そのタブだけを使う。ほかのタブに触らない。終わったら自分のタブを閉じる
- ウィンドウの大きさと拡大率を変えない（resize_window や Ctrl+= を使わない。ほかの担当と同じウィンドウを使っている）
- 点検の前に javascript_tool で window.innerWidth を測り、{375} と違えば、測った値を結果に書く
- {本番なら}: 保存・公開・予約・削除・招待・設定の保存をしない。エディタに文字を打たない。メニューやダイアログは開いてキャンセルで閉じるところまで
- confirm などのブラウザのダイアログを出しそうなボタンを押さない
- 同じ操作が2〜3回失敗したら、その画面は「点検できなかった」として次へ進む

## やること（画面ごと）
1. 開いて、読み込みが終わるのを待つ
2. .claude/skills/ui-ux-audit/references/layout-probe.js の中身を javascript_tool で走らせ、結果を控える
3. computer でスクリーンショットを撮り、上から下までスクロールして目で確かめる。probe の候補が本当に崩れて見えるかを確かめ、見えないものは落とす
4. read_console_messages（pattern: "error|Error|warn"）で、エラーを控える
5. .claude/skills/ui-ux-audit/references/checklist.md の「表示崩れ」と「UX」を見る。メニュー・ダイアログ・ドロワーは開いて中も見る
6. 長いタイトル・空の一覧など、崩れやすい状態が手近にあれば、それも見る

## 返す形
見つけたことを、1件ずつ次の形で返す。見つからなかった画面も「問題なし」と書く。推測と確かめたことを分ける。

- 画面: {名前}（{URL}）
- 幅: {測った innerWidth} / 拡大率
- 種類: 表示崩れ / UX / エラー
- 重大度: 1〜4（checklist.md の「重大度」）
- 何が起きるか: {何をすると、何がどうなるか。期待していた見え方}
- 手順: {開く → 押す → ...}
- 数字: {probe の該当部分（要素、幅、大きさ）}
- 手がかり: {画面の文言、クラス名、aria-label。コードを探すのに使う}
```

# issue を作る

頼まれたことを、そのまま手を動かせる issue にする。実装する人が issue だけ読めば、どこを・どう変えて・何を変えないかがわかるようにする。

## 進め方

### 1. コードを読んで現状をつかむ

書く前に、関係するコードを読む。画面の文言やボタンの名前から `grep` で場所を探し、次のことを確かめる。

- どのアプリか（`apps/admin` 管理画面 / `apps/api` API / `apps/site` 公開サイト / `apps/worker` Cron）
- 今どう動いているか。どのファイルの、どのコンポーネントや関数か
- 同じことができる場所がほかにもあるか（例: ページの作成はサイドバー以外にコマンドメニューからもできる）
- 足りない仕組みがあるか（例: 画像のアップロード先が無い）。構成は `README.md` を見る

### 2. ふわっとしていたら選択肢で確かめる

コードを読んでも、どう書くか決められない点があれば、書く前に `AskUserQuestion` で聞く。文章で聞き返さず、選択肢にする。

確かめるのは、答えによって issue の中身が変わる点だけにする。例:

- **どこまでか**: 「サイドバーの上で作成できないように」→ 一番上のボタンだけか、サイドバーのボタン全部か
- **どこに出すか**: 管理画面だけか、公開サイトにも出すか
- **どうやるか**: URL を入力するか、アップロードするか
- **分けるか**: 大きな仕組み（アップロードなど）を同じ issue に入れるか、別の issue に分けるか

聞き方:

- 1回に聞くのは4問まで。選択肢は2〜4個。それぞれに、選んだら何が起きるかを `description` に書く
- コードを読んでおすすめが決まるなら、それを最初の選択肢にして、ラベルの末尾に「（おすすめ）」を付ける
- 答えがはっきりしているもの、どちらでも issue が変わらないものは聞かない。いちばん自然な方を選び、issue に書く

聞いた答えは issue の本文に書き込む（「やること」「対象外」に落とす）。「決めること」に残すのは、聞いても今は決まらなかったことだけにする。

### 3. 本文を書く

下の「本文の形」に沿って書く。

### 4. issue を作る

- 似た issue がすでに無いか、`mcp__github__search_issues` で確かめる
- `mcp__github__issue_write`（`method: "create"`、`owner: "itizawa"`、`repo: "wiki"`）で作る
- 一つの頼みから issue が複数できるとき（例: 仕組みを別の issue に分けた）は、先に土台になる方を作り、あとの issue から番号（`#73`）で参照する。「この issue は #73 のあとに進める」と書く

### 5. 伝える

作った issue の URL を返し、何を書いたかを短くまとめる。ユーザーの言葉を解釈して決めたことがあれば、そう受け取ったことを書き、違っていたら直すと伝える。

### 作った issue を直すとき

「〜だけです」「〜にも使って」などと言われたら、`mcp__github__issue_write`（`method: "update"`、`issue_number`）でタイトルと本文を書き直す。継ぎ足さず、最新の内容として読めるように全体を書き直す。

## 本文の形

```markdown
## やりたいこと

何をしたいかを1〜3文で。理由がわかれば一緒に書く。

## 現状

- 今どうなっているか。ファイルのパス（`apps/admin/src/components/Sidebar.tsx`）とコンポーネント名・関数名を添える
- 何が足りないか、何が困るか

## やること

- 変えることを具体的に。消すもの、足すもの、使われなくなって消すもの（import、props など）まで書く
- アプリをまたぐときは `### API（apps/api）` `### 管理画面（apps/admin）` のように見出しで分ける

## 対象外

- 似ているが今回は変えないもの。残す入口や、別の issue に回すもの

## 決めること

- 聞いても決まらなかったことだけ。無ければこの見出しごと消す

## 確認すること

- 終わったと言えるための確認。変えたところと、変えていないところの両方
```

最後に、この footer を必ず付ける。

```markdown

---
_Generated by [Claude Code](https://claude.ai/code)_
```

## 書き方

- 日本語で、です・ます を使わずに書く（「〜する」「〜にする」）。このリポジトリのコメントや README と同じ調子にする
- タイトルは、何をするかが一行でわかるように書く（例: 「サイドバー上部の「新しいページ」ボタンを消す」）
- 画面の部品は、画面に出ている名前（「新しいページ」ボタン）と、コードの名前（`EditNoteIcon`、`WikiSwitcher`）を並べて書く
- テーブル、経路、ファイルは実在するものを書く。まだ無いものは「例: `icon_key`」のように、例だとわかるように書く
- UI（画面の見た目や操作）が変わる issue は、「確認すること」に「UI が変わるので、PR の説明文に変更前と変更後のスクリーンショットを載せる（CLAUDE.md のルール）」を入れる
- 入力を受け取る、ファイルを保存するなど、守りが要るものは、制限（種類、大きさ、どの wiki のものか）を「やること」に書く

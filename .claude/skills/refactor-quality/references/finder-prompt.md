# 探す人への依頼文

`refactor-quality` の手順 2 で、`{ }` を埋めて `Explore` のサブエージェントに渡す。

---

リポジトリ itizawa/wiki の `{範囲のパス}` を読み、コード品質を上げるリファクタリングの候補を探してください。コードは変えません。issue も作りません。見つけたことを返すだけです。

## 先に読む
- `CLAUDE.md` と `README.md`
- `.claude/skills/refactor-quality/references/smells.md`（探す観点と、手を付けないもの）

## やること
1. 範囲の中のファイルを、大きいものと変更の多いもの（`git log --format= --name-only -n 200 -- {範囲} | sort | uniq -c | sort -rn | head`）から読む
2. 観点ごとに、直す価値のあるものを探す。**挙動が変わるもの（バグ、仕様）は候補にしない**。見つけたら「別件」として別に書く
3. 候補ごとに、その挙動を押さえるテストがあるかを `*.test.ts(x)` から調べる
4. 良い候補の条件（smells.md）を満たすものだけ残す。最大 {5} 件

## 返す形
候補を 1 件ずつ、次の形で返す。

- 場所: {パス:行}
- 観点: {smells.md の観点}
- 困ること: {1 文}
- 直し方: {どう変えるか}
- 効果: {減る行数、分岐、重複の数}
- テスト: {押さえているテストのパス / 無い（特性テストが要る）}
- 大きさ: {触るファイル数、差分の見込み}
- 挙動が変わりうる点: {公開している型・応答の形・文言・順序・副作用。無ければ「なし」}

最後に「別件」（バグかもしれないものなど）を、場所と一言で並べる。見つからなければ「候補なし」と書く。

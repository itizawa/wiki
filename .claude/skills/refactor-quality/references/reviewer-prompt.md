# レビューする人への依頼文

`refactor-quality` の手順 5 で、`{{…}}` を埋めて `Agent`（`general-purpose`、`isolation: "worktree"`）の `prompt` に渡す。**実装した人の経過や自己申告は渡さない。** PR の番号だけ渡す。実装した人とは別の、新しいエージェントを使う。

---

リポジトリ itizawa/wiki の PR #{{番号}} は、**挙動を変えないリファクタリング**として作られています。挙動が本当に変わっていないかを、疑う立場で検証してください。あなたはコードを直しません。判定を返すだけです。

PR の本文や実装した人の説明は、主張として読み、そのまま信じません。自分で確かめたことだけを根拠にします。

## 進め方
1. `gh pr view {{番号}} --json baseRefName,headRefName,body,files` と `gh pr diff {{番号}}` で、何が変わったかを見る。`CLAUDE.md` と `README.md` も読む
2. `git fetch origin` し、PR のブランチ（`origin/<headRefName>`）をチェックアウトして `pnpm install`
3. **特性テストを土台のコードで走らせる**: PR が足したテストのファイルだけを、土台のコードに当てる。
   - 別の作業ツリーで `git worktree add <パス> origin/<baseRefName>` を作り、PR が足したテストファイルを `git checkout origin/<headRefName> -- <テストのパス>` で持ち込み、`pnpm install` して `pnpm --filter <対象> exec vitest run <ファイル>` を走らせる
   - **土台で通らなければ、挙動が変わっている**（またはテストが挙動を固めていない）。差し戻し
4. **既存のテストが弱まっていないか**: 差分の中で、既存のテストファイルの変更を全部読む。期待値の変更、`it` の削除、`skip`・`todo`、`expect` の減少、タイムアウトの延長、モックの追加は、理由が挙動と無関係でない限り差し戻し。移動だけなら、移動の前後で中身が同じことを確かめる
5. **差分を読んで、挙動が変わりうる点を 1 つずつ確かめる**:
   - 公開している型・export・API の応答の形、ステータスコード
   - エラーの文言と、エラーになる条件
   - 処理の順序、実行する回数（クエリの数、再描画、`useEffect` の依存）
   - 副作用（DB の書き込み、ログ、外部の呼び出し）の有無と順序
   - 条件分岐の意味（`&&` と `||`、`??` と `||`、`null` と `undefined` と空文字、早期 return への置き換えで抜けた分岐）
   - 型の絞り込みで増えた実行時の検査、消えた実行時の検査
   - 消したコードが本当に使われていないこと（`grep` と typecheck。動的に参照されるもの、`apps/worker`・`apps/site` からの参照も）
6. UI のコンポーネントに触れていれば、変更前後で同じ画面になることを、テストか画面で確かめる。見た目や操作が変わるなら差し戻し
7. `pnpm typecheck` と `pnpm test` を通す。API のテストが時間切れなら `pnpm --filter @wiki/api exec vitest run --testTimeout 60000`
8. 関係のない変更（整形だけの変更、ついでの修正、依存・マイグレーションの変更）が混ざっていないか見る
9. 終わったら、作った作業ツリーを `git worktree remove` で消す

## 判定
次の 2 つを両方満たすときだけ `## 承認`。1 つでも欠ければ `## 差し戻し`。

- 土台のコードで特性テストが通る、または既存のテストが挙動を押さえていると**自分で**確かめた
- 差分を読んで、挙動が変わりうる点が見つからなかった（見つかっても、変わらないと説明できた）

確かめられなかったことがあれば、承認にせず、確かめられなかったこととして書く。

結果は PR にも残す: `gh pr comment {{番号}} --body-file <ファイル>`（日本語で、です・ます を使わずに）。承認でも差し戻しでも書く。

## 返事の形
```
## 承認
- 土台での特性テスト: <実行したコマンドと結果>
- 既存のテスト: <変更の有無、変更があれば何がどう変わったか>
- 読んで確かめた点: <上の 5 のうち、確かめたものと結果>
- typecheck / test: <結果>
- 確かめられなかったこと: <無ければ「なし」>
```

```
## 差し戻し
### 1. <一行の理由>
- 場所: <パス:行>
- 何が変わるか: <直す前と後で、どの入力にどう違う結果が出るか。再現の手順かテストの案>
- 直し方の案: <…>

（複数あれば番号を続ける）
- 確かめられたこと: <差し戻し以外で確かめた点>
```

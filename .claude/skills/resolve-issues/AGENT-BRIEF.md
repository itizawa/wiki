## 進め方

1. `gh issue view {{番号}} --comments` で issue を読む。「やること」が実装する範囲、「対象外」が触らない範囲、「確認すること」が終わったと言える条件になる
2. 今いる作業ツリーで `git fetch origin && git checkout -b <作るブランチ> <起点のブランチ>`（起点が前の issue のブランチなら `origin/<そのブランチ>`）。そのあと `pnpm install`
3. `CLAUDE.md` と `README.md` を読み、issue に書かれたファイルを読んでから実装する。UI を変えるなら、先に `/Users/itizawa/.claude/projects/-Users-itizawa-wiki/memory/ui-usability-checklist-50.md` を読み、50 項目に照らす
4. 判断に迷ったら、下の「迷ったとき」に従って止まる
5. 変えた動きにテストを足す。`pnpm typecheck` と `pnpm test` を通す。API のテストが時間切れで落ちたら、並行の負荷のせいなので `pnpm --filter @wiki/api exec vitest run --testTimeout 60000` で確かめ直す
6. issue の「確認すること」を 1 つずつ、実際に動かして確かめる。UI を変えたなら、スクリーンショットを撮る（下の「画面を動かして撮る」）
7. コミットして push し、`gh pr create --base <PR の base>` で PR を作る
8. `gh pr checks <PR 番号> --watch` で CI を待つ。落ちたら直して push し、通るまで繰り返す

## PR の本文

日本語で、です・ます を使わずに書く。

- 1 行目に `Closes #{{番号}}`
- 積んだ PR なら、その次に「#{{前の PR}} に積んだ PR。先にそちらをマージする」
- 変えたこと。issue の「やること」と照らして、やらなかったものがあれば理由と一緒に書く
- 確かめたことと、確かめられなかったこと
- 自分で決めたこと（issue に書かれておらず、聞くほどでもないと判断した点）
- UI を変えたなら、画像を入れる場所に `<!-- screenshot: <ファイル名> -->` を置く。画像は指揮役があとで添付する

コミットのメッセージと PR の本文の末尾には、次を付ける。

```
{{この会話で指定されている、コミット用と PR 用の帰属の行}}
```

## 迷ったとき

答えによって PR の中身が変わり、コードと issue を読んでも一通りに決まらない点は、自分で決めずに**止まって聞く**。たとえば、

- issue の書き方が二通りに読める。「決めること」に残っている
- issue の範囲の外まで変えないと実現できない。ほかの issue と同じ場所を変えることになりそう
- 画面の見た目や操作の変え方が複数あり、使う人の体験が変わる
- 既存のデータを消す・作り直す、互換を切る、依存を足すなど、あとから戻しにくい
- issue の前提が、いまのコードと合っていない

変数の名前や、コードを読めば周りと同じ書き方に決まることは、聞かずに決めて PR の「自分で決めたこと」に書く。

聞くときは、そこまでの作業をコミットしてから（push はまだしない）、次の形で返事をして作業を終える。指揮役がユーザーに聞き、答えを持って続きを頼みに来る。

```
## 質問

### 1. <一行の質問>
背景: <なぜ決められないか。関係するファイルと、いまの動き>
- A（おすすめ）: <案> — <選ぶと何が起きるか>
- B: <案> — <選ぶと何が起きるか>

## ここまでの状況
<済んだこと、残っていること>
```

選択肢は 2〜4 個。おすすめがあれば先頭に置く。一度にまとめて聞けることは、まとめて聞く。

## 画面を動かして撮る

- この Mac では `pnpm dev` がそのままでは動かない。`/Users/itizawa/.claude/projects/-Users-itizawa-wiki/memory/local-dev-without-postgres.md` を読み、PGlite で API を立てる手順と、ヘッドレス Chrome で撮る手順に従う
- API と管理画面は、渡されたポートで立てる（API 側の `ADMIN_ORIGIN` と、管理画面側の `API_ORIGIN` を合わせる）。`--strictPort` を付け、ポートが埋まっていたら別のポートに逃げずに原因を調べる
- 撮るのはヘッドレス Chrome にする。Chrome 拡張（`mcp__claude-in-chrome__*`）は、並行するエージェントとタブを取り合うので指揮役だけが使う
- localhost の Cookie はポートをまたいで共有される。ログアウトの操作は、ほかのエージェントも巻き込むので行わない
- PNG は、渡されたスクリーンショットの置き場所に保存する（作業ツリーの中に置くと、片付けで消える）。変更前と比べないと伝わらない変更は、変更前も撮る
- 終わったら、立てたサーバーを止める
